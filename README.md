# 扉は何も言わない（tobira3d）

一人称3Dの脱出ゲーム。部屋ごとに一つの言いつけに従い、正しい扉をくぐる。
正誤は扉を通るまで分からない。手がかりと正解の扉はシードで毎回変わる。

- **はいる**（通常）：第1〜5室を一度も失敗せずに抜ければクリア。間違えれば新しいシードで第1室から。
- **無限モード**：部屋はどこまでも続き、だんだん紛らわしくなる。一度でも間違えれば終わり。

## 起動

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # dist/ に静的ファイル（どこにでも置ける。base は相対パス）
npm run preview    # build したものを確認
npm test           # 全部屋の自動テスト（node）
npm run textures   # テクスチャを Poly Haven から取り直す（同梱済みなので通常は不要）
```

## 遊び方

| | PC | スマホ |
|---|---|---|
| 移動 | WASD / 矢印 | 左下の仮想スティック |
| 見回す | 左ボタンを押したままドラッグ（カーソルは固定されず、いつでも画面の外へ動かせる） | 右側をドラッグ |
| 調べる・扉を開ける・拾う | 画面中央の印を合わせてクリック（ドラッグせずに離す） / E | 見たい物をタップ |
| 持ち物を使う | F | 右下の「使う」 |
| 一時停止 | Esc | 右上の II |
| ミュート | M | 右上の ♪ |

- 歩く速さは1つだけ（走る操作はない）。スティックはどれだけ倒しても同じ速さ。
- 遊んでいる間、画面の左下（スマホは左上）に「WASD 移動 / ドラッグ 見回す / クリック 調べる」を小さく出している。
- 画質は タイトル／一時停止画面で 高・中・低・自動 を選べる。自動はスマホで「中」から始め、重ければさらに下げる。
- 音量は タイトル／一時停止画面で「環境音」「効果音」を別々に調整できる（localStorage に保存）。
- 環境音はゲームを始めてから鳴る。タイトル・一時停止中・タブが非表示の間は止まる。
- 記録（最高到達・挑戦回数・最短踏破・無限モードの最高到達室数とそのシード）は localStorage に保存。

## シード

- 挑戦を始めるときにシード（1〜999999999）を決める。タイトル画面と一時停止画面に表示する。
- URL に `?seed=数字` を付けるとそのシードで始まる（例：`http://localhost:5173/?seed=12345`）。無限モードの最高記録のシードもタイトル画面に出る。
- 通常モードで失敗すると、前のシードと挑戦回数から新しいシードを決めて第1室からやり直す（`nextSeed`）。
- 乱数は `src/core/rng.ts` の mulberry32。部屋ごとに `hash32(シード, 部屋番号, 用途)` で別の乱数列を作るので、ある部屋の作り方を変えても他の部屋はずれない。
  用途は「手がかり（room）」「部屋の種類（kind）」「小物の仕掛け（plan）」の3つ。
- core と rooms では `Math.random` を使わない（テストで検査）。同じシード・同じ操作なら、挑戦全体が完全に再現される。

## 部屋（5種類）

部屋の仕組みは5種類だけで、シードと難しさ（lv）で手がかりを変えて使い回す。

| 種類 | 部屋 | 言いつけ | シードで変わるもの | lv が上がると |
|---|---|---|---|---|
| 灯り | ホテルの廊下 | 「灯りのともる扉へ」 | 灯る扉・部屋番号 | 扉が4枚に、「灯りの消えた扉へ」も出る、扉のない壁にもランプ |
| 音 | 深夜のオフィス | 「鳴っている電話の机の番号の会議室へ」 | 鳴る机・点いている画面 | 机・島・会議室の番号がばらばら、ベルの間隔が空く |
| 待つ | 夜間外来の待合室 | 「お呼び出しまでその場から動かないでください」 | 呼ばれる時刻と診察室 | 診察室の番号がばらばら、途中に「しばらくお待ちください」 |
| 数える | 月見の座敷 | 「赤き物の数の襖を開けよ」 | 赤い物（7つの候補から2〜6個） | 数が増える、屏風の裏の傘が赤いことが多い、選択肢が隣り合う |
| 暗転 | 地下倉庫 | 「灯が消えて戻ったら動いたものの扉へ」 | 動く物（イス・ハコ・ニンギョウ）と暗くなる時刻 | 札の並びが入れ替わる、動く距離が縮む、引きずった跡・埃の跡が消える |

- 第1〜5室は 灯り→音→待つ→数える→暗転 の順。第6室からは種類をシードで選び、同じ種類は続かない。
- lv ＝ `floor((部屋番号 − 2) / 4)`（第7室から4室ごとに1段）＋ 紛らわしさ。上限 8。
- どのシード・どの lv でも、言いつけと手がかりから正解の扉が1つに決まる（テストで確認）。

## 小物

持ち物は同時に1つだけ。部屋に落ちている小物を「調べる」で拾い、F（スマホは「使う」）か、使う対象を調べて使う。
持っているときに別の小物を拾うと持ち替えになり、持っていた物はその場に置く。持ち物は次の部屋へ持ち越せる。

| 小物 | 使い方 | 別解 |
|---|---|---|
| 懐中電灯 | 暗がり（壁の低い所の黒ずみ）の近くで使う | 正解の扉の札がチョークで書いてある。電池が切れる |
| 鍵 | 鍵の扉（南京錠つき）を調べる／近くで使う | 鍵の扉は言いつけに関係なく次の部屋へ通じる（待つ・暗転も飛ばせる）。鍵は消える |
| メモ | どこでも | その部屋のヒントを1つ見せて消える |

- 各部屋に小物が1つ落ちていて、それを使った別解が必ずある。待合室のメモは入口のすぐ横（動かずに拾える）。
- **紛らわしさ**：小物を使うと増える（メモ +2、懐中電灯・鍵 +1、上限 6）。小物を使わずに部屋を抜けると1減る。次の部屋の lv に足される。一時停止画面に表示。
- 鍵・懐中電灯を持ったまま次の部屋に入ると、その部屋には必ず鍵の扉・暗がりがある（待合室に暗がりはない）。
- 失敗して第1室に戻ると、持ち物と紛らわしさは消える。

## 仕組み

```
src/
  core/        three.js に依存しない判定（node でテストできる）
    game.ts      進行・裏の判定・扉の通過タイムライン・リスタート・記録・小物・紛らわしさ
    rng.ts       シード付き乱数（mulberry32・hash32・nextSeed）
    types.ts     部屋定義の型
    replay.ts    操作列の自動再生（テストとデバッグで共用）
  engine/      見た目と操作
    app.ts       60Hz 固定ステップのループ、部屋の読み込み/破棄、扉を通る演出、調べる
    kit.ts       部屋を組み立てる道具（壁・扉・照明・看板・当たり判定・音）
    view.ts      描画（ACES、影、霧、GTAO、ブルーム、SMAA、グレイン、ビネット、色収差）
    player.ts    歩行（加減速・壁ずり・ヘッドボブ・足音のタイミング）
    audio.ts     Web Audio の合成音（足音は床の素材別、HRTF の立体音響、部屋の残響）
    input.ts     キーボード・マウス・タッチ
    materials.ts テクスチャと、コードで描く畳・紙・看板
    extras.ts    小物・錠前・暗がり・懐中電灯の光（どの部屋でも共通）
  rooms/       部屋の作り方（1種類=1ファイル）
    index.ts     部屋の生成（種類の並び・難しさ・小物の仕掛け）
    common.ts    小物の仕掛けと別解を足す finish()
```

### 扉の切り替え（フェードなし）
全ての扉の向こうに、同じ形・同じ焼き込み照明（ライトの影響を受けない素材）の小部屋がある。
扉をくぐってこの小部屋に入り、背後の扉が閉まった瞬間に前の部屋を破棄して次の部屋を読み込む。
次の部屋の入口の扉の裏にも同じ小部屋があり、カメラの相対位置はそのままなので、つなぎ目は見えない。
正解・不正解で扉の動き・音・時間（くぐり始めから次の部屋で動けるまで約2秒）は完全に同じ。結果は次の部屋で初めて分かる。

## 部屋の追加方法

部屋は「乱数とプランから `RoomDef` を作る関数」。新しい仕組みを足すより、既存の種類の手がかりの変え方を増やす方を先に考える。

1. `src/rooms/r06-xxx.ts` に `export function xxxRoom(r: Rng, p: Plan): RoomDef` を作る（既存の部屋をコピーするのが早い）。
   - 手がかり・正解・札はすべて `r`（その部屋専用の乱数列）から決める。`p.lv` で紛らわしさを変える。
   - `shell`：広さ・床/壁/天井の素材・霧・環境音・足音の種類
   - `doors`：扉の壁（n/e/w）・位置・札・様式（hotel/office/hospital/fusuma/metal）
   - `answer`：正解の扉が `doors` 配列の何番目か（0始まり）
   - `spec`：生成に使った値（テストで「同じシードなら同じ」を確かめる）
   - `logic`：`init` / `update`（60Hz）/ `interact` / `check`（言いつけを破ったら理由を返す）/ `miss`（扉違いの理由）
   - `build(kit)`：家具・照明・看板・音を置く。`kit.at(秒, fn)` で時刻に合わせた演出
   - `solution`：正解の操作列。`wrongs`：失敗すべき操作列
   - 最後に `finish(base, r, p, {...})` で小物の仕掛けを足す：鍵の扉の場所（`lock`）、小物の置き場所（`items`）、暗がりの場所（`darks`）、
     扉をくぐってよい最短の時刻（`earliest`）、メモのヒント（`hint`）。別解の操作列は `finish` が作る。
2. `src/rooms/index.ts` で `RoomKind` に種類を足し、`FACTORY` と `ITEMS` に登録する（無限モードの並びに自動で入る。第1〜5室に入れるなら `FIRST` にも）。エンジンは触らなくてよい。
3. `npm test` で、シード1〜200の全てで「正解の扉だけが通れる」「wrongs が失敗する」「別解で通れる」「同じシードで同じ部屋」「無限モードで第30室まで踏破」を確認する。

失敗理由は「次に活かせる1行」にする。判定に `Math.random` は使わない（テストで検査している）。

- 畳・襖・掛け軸・看板・貼り紙・ホワイトボード・夜景・埃の跡などの模様と文字（Canvas）
